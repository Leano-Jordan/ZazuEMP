# Playwright database safety

## Registration E2E is opt-in

The registration flow in `e2e/onboarding.spec.js` creates a persistent user and business through the real Laravel registration endpoint. It must never run against a developer's normal Zazu database or an installed business database.

The test is skipped unless **both** environment variables are explicitly set in the Playwright process:

- `ZAZU_E2E_ALLOW_REGISTRATION=1`
- `ZAZU_E2E_ISOLATED_DATABASE=1`

These are deliberate operator acknowledgements, not automatic database isolation. Setting them does not create or verify a disposable database. Before opting in, the operator must ensure the Laravel server used by Playwright is configured to a disposable database containing no business data.

## Current local Playwright behavior

`playwright.config.js` permits reuse of an already-running local server outside CI. That means a browser test can reach the developer's existing application process and whichever database that process has loaded. Never infer database isolation from Playwright starting successfully or from a test name containing "browser".

For ordinary local UI/offline tests, leave the registration opt-in variables unset. The registration test will report as skipped. CI's dedicated offline-browser workflow prepares its own SQLite database before starting the application; the registration flow is not part of that workflow's selected test files.

## Cleanup

Synthetic workspaces generated by the registration spec use the exact business-name format:

`Browser Catering ` followed by ten hexadecimal characters.

The targeted Artisan cleanup command matches only that format. It is a recovery tool, not a substitute for preventing test pollution.
