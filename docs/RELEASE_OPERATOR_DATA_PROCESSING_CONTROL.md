## Purpose

Provide a checklist for situations where another person or organisation processes personal information on behalf of the responsible party.

## Before processing begins

Record:

- responsible party;
- operator;
- service/function provided;
- categories of personal information;
- categories of data subjects;
- processing purposes;
- locations/systems used;
- sub-operators, if any;
- access method;
- security controls;
- retention and disposal instructions;
- incident-notification route;
- end-of-service return/deletion obligations.

## Written terms should address

- processing only on documented instructions;
- confidentiality/access restrictions;
- reasonable security measures;
- breach/security-compromise notification to the responsible party;
- assistance with applicable data-subject requests;
- deletion/return at contract end subject to lawful retention;
- sub-operator approval/control;
- evidence and audit cooperation;
- restrictions on secondary use.

## Zazu-specific deployment questions

Confirm whether the deployment actually uses:

- hosted infrastructure;
- cloud storage;
- email delivery providers;
- analytics;
- customer-support systems;
- payment processors;
- messaging/WhatsApp integrations;
- external backup storage;
- managed IT providers.

Do not list a provider merely because the framework can support it.

## Current technical boundary

The current repository is designed around authenticated users, business-scoped data, private media and local/online operating modes. The existence of a secure technical boundary does not remove the need for an appropriate contract where another party processes personal information.
