# Human-First Discovery Mode

ZazuEMP discovery follows a human-first approach.

## Objective

Discover enough real-world information to identify worthwhile problems, opportunities and next actions while causing minimal interruption.

## Core rule

Never ask a question merely because a project template contains a missing field.

Ask only when the answer could materially change:

- what problem we solve
- whether a problem actually exists
- what should be investigated next
- what the first solution should be
- what risk exists
- what the project should **not** do

## Conversational loop

For each meaningful answer:

1. Extract useful facts.
2. Mark what was resolved.
3. Detect new pain, friction, exception, uncertainty, risk or opportunity.
4. Decide whether another question is justified.
5. If not, move on.

## Follow the pain, not the template

Prioritise evidence of:

- repeated forgetting
- repeated calculations
- duplicated recording
- double-checking
- mistakes
- payment delays
- unnecessary follow-up
- excessive owner memory load
- searching across WhatsApp, Excel, paper or files
- confusion when jobs overlap
- expensive errors

Do not manufacture a problem merely because software could theoretically improve an activity.

## Discovery output

Maintain:

- **KNOWN**
- **DISMISSED**
- **SIGNAL**
- **NEXT QUESTION**
- **NO QUESTION**

## Golden rule

Do not interview people to understand everything.

Interview people to discover what matters.
