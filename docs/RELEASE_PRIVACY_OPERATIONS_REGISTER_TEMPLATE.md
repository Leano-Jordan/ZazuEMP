# Zazu EMP — Privacy Operations Register Template

**Use:** controlled owner/operator administration only. This is a blank structure, not a system feature or proof of compliance.

**Storage rule:** keep the working register in an access-restricted location outside the Git repository and ordinary support tickets. Do not commit completed registers, identity documents, request attachments, incident evidence or personal information to GitHub. Record only minimum metadata and a controlled reference to the protected evidence location.

**Handling note:** do not assume that a customer’s request about its own client records is automatically a request to the Zazu software provider. Identify the responsible party and operator relationship first. Preserve records only where an applicable legal, contractual, accounting, security or evidentiary reason authorises retention; document the reason and review date.

**Critical rule:** do not use the S1–S4 severity rating as a POPIA notification threshold. If there are reasonable grounds to believe personal information was accessed or acquired by an unauthorised person, escalate immediately. An operator must notify the responsible party immediately; the responsible party assesses and makes the required regulator/data-subject notifications as soon as reasonably possible. Do not wait for a completed investigation.

## 4. Periodic operational review

- [ ] Actual providers and sub-operators are inventoried.
- [ ] Incident escalation and eServices access are tested.
- [ ] Retention, deletion, private-media disposal and backup expiry are verified.
- [ ] Information Officer appointment/registration and PAIA manual status are checked.
- [ ] Legal/operational review date and unresolved issues are recorded.
