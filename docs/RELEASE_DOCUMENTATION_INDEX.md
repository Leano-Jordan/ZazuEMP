## Completion rule

A document is not considered release-complete merely because this repository contains the file.

Final closure requires:

1. Actual responsible-party/customer details to be inserted.
2. The procedure to match the real deployment model.
3. Legal/accounting review where the subject is legally material.
4. Technical controls to be verified against the current release.
5. Evidence of the final document version retained with the release record.

## Non-negotiable placeholders

Do not invent these values in the repository:

- legal entity name;
- registered address;
- Information Officer / Deputy Information Officer identity;
- privacy contact address;
- support SLA;
- retention periods required by law;
- tax/accounting conclusions;
- trade-mark clearance status;
- customer pricing or commercial promises.

Those values must be supplied from the real business arrangements.

## Release position

The documentation set closes the **documentation-design gap**. It does not by itself close legal/privacy readiness. The implementation audit identifies which controls already exist, which are manual/procedural, and which are not currently implemented.
